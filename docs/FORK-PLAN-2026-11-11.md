## A. Двери, рычаги, лифты

### Что делает 1.0.9 [VAR]
- По сети ходят только event-флаги (`world.rs:200-222` should_sync, `apply_flag` `world.rs:943-1007`,
  join-снапшот записей хоста).
- `doors.rs` (вызов каждый кадр, `world.rs:917`): если друг включил флаг двери, а наша дверь загружена и
  закрыта, через 300 мс её открывает повтор `0x6BA910(block, index, actor=-1, state=1)`
  (`doors.rs:599-626`, `456-481`). Guard 2/3 защищают флаг от выключения нашим переключателем и от OFF друга.
- Нативный пакет type 45 (ObjAct по игровому неткоду) уже реализован (`nsession.rs:829-837`, `911`,
  `1253`, `2235-2236`), но включается только при `native_session_stage = 4`; по умолчанию 3
  (`settings.rs:390`, `692`). Работает только пока нативная сессия engaged (оба в одном блоке).

### Почему у второго игрока открывается «только анимация» [ARV]
- Состояние двери живёт в `SprjWorldObjActMan` (info: run state `+0x54`, state-объект `+0x88`,
  байты `+113/+114`) и в объекте карты; event-флаг есть только у классов Door / OneLoop / OneDirDoor.
  У OneState флага нет, его ставит EMEVD. Пришедший флаг меняет только флаг, объект собирается из флагов
  при загрузке блока.
- Живой скан (JATKA-TASTA-MULTIPLAYER.md:116): one-state 24, door 0, one-loop 9. То есть большинство
  дверей — OneState, `scan()` их пропускает (`doors.rs:259`), fallback ничего не повторяет
  (`doors.rs:615-618`). Объект у второго игрока закрыт до перезагрузки (риск описан в
  IMPLEMENTATION-NOTES:1400).
- «Видна анимация» — скорее всего реплика друга играет анимацию игрока у ObjAct и визуально проходит
  сквозь закрытую дверь. Если двигается сама створка, а пройти нельзя — это одна из 9 OneLoop,
  повторённых с актёром -1 [Г]. Различать по строке `doors: the friend opened a door … (0x6BA910 ok = …)`.

  `nsession: evidence tx|rx type 45`. Пакет 45 → `0x6BE740` → `0x6BA910(block, index, actor, state)`
  с актёром (IMPLEMENTATION-NOTES:1164). Если дверь становится проходимой — вопрос «чем открывать» закрыт.
- **A1, своё сообщение ObjAct (2–3 дня).**
  - Отправитель: детур на `0x6BC1B0` (исполнение ObjAct), только когда актёр — наш локальный игрок.
    Свой `0x6BA910` помечать в TLS против эха.
  - Сообщение по надёжному каналу world.rs: `{map block id, info index (+0x08), sub (+0xAC),
    ObjActParam id, target state, seq}`. Индекс блока в WorldObjActMan не годится (зависит от порядка загрузки).
  - Получатель на игровом потоке: найти блок по map id, проверить run state ≠ 3 и
    `looks_open() == Some(false)`, вызвать `0x6BA910(block, index, actor, state)`. Актёр -1; если A0
    покажет, что проходимость зависит от актёра — передавать handle реплики друга.
  - Покрывает все классы, включая OneState и сундуки. Флаги остаются источником правды для сейва.
- **A2, лифты и рычаги.** Слать целевое состояние, не «переключить». Не повторять, пока info исполняется
  или наш игрок стоит на платформе. Учесть относительные позиции реплики на движущемся объекте
  (IMPLEMENTATION-NOTES:244, 250).
- **Логи первыми:** на каждое локальное исполнение ObjAct — map id, index, sub, класс, флаг до/после,
  ObjActParam id, entity, анимация объекта до/после, все флаги групп 1/2 за ±5 с (сейчас world.rs логирует
  только первые 30 и каждый сотый, IMPLEMENTATION-NOTES:1162). У получателя — состояние той же info через
  1 и 3 с. Горячая клавиша «прошёл / не прошёл».

Риски: ключевые двери открываются без ключа (ок, флаги общие); двери без сохраняемого состояния
закроются у перезагрузившегося; двойное срабатывание вместе с type 45 отсекается `looks_open`.

## B. PvP

### Что есть в 1.0.9 [VAR]
- Кода PvP нет вообще. Команда пишется только реплике при спавне `0x9F5170(chr, 1)` (`native.rs:67`,
  `103-104`), реплика получает team 2 (RE-ENEMY-TARGETING.md). Матрица команд `0x143B0CAA0`: 1 и 2 не
  враждебны, хитбоксы игроков друг друга не задевают. 29 = Indiscriminate (WEB-PRIOR-ART.md:144).
- Роутер урона `0xB6A040`: таблицы `u32[7][7]` по `0x2A7C590`/`0x2A7C660`, индекс
  `[класс жертвы][класс атакующего]`; классы: 1 локальный игрок, 2 удалённый, 3–6 NPC
  (IMPLEMENTATION-NOTES:498-505, 687; `artfx.rs:41-51`, `85-91`). Action 0 только реакция, 2 применить и
  послать 21 хосту, 3 применить и разослать всем. Строки 1 и 2 таблиц (игрок против игрока) НЕ прочитаны.
- Урон по реплике `0xB729E0` уводит в `0xB68FF0(…, remote=1)` — реакция без HP; HP реплики из пакетов
  type 1 (RE-FINDINGS-2). Нативный пакет 21 умеет «урон по игроку»: `+0` netId жертвы, `+0xC` атакующий,
  применение `0xA4F940 → 0x8D77B0 → 0xB680C0/0xB68FF0` (SPEC-NATIVE-SESSION.md:145).
- Sekiro Online (LukeYui) считал урон у атакующего (RE-SEKIRO-ONLINE.md); 1.0.11, судя по
  `pvp_hit_action = 2` и `pvp_team = 29`, — у жертвы против реплики, отстающей на 130–200 мс при
  ~12 пакетах/с. Отсюда «попало на экране, засчиталось через раз» [ARV].

### Рекомендация: гибрид
Детекция у атакующего, у жертвы проверка по кольцевому буферу своего состояния за ~500 мс
(i-frames, guard, deflect) на момент «сейчас минус односторонняя задержка». Чисто жертва с
лаг-компенсацией отклонена: Havok-детекцию не откатить.

### План
- **B0, IDA (1 день).** Прочитать строки 1–2 обеих таблиц и actions 1/4–7; доходит ли удар по жертве
  класса 2 до `0xB6A040` или его перехватывает `0xB729E0`; что делает `0xB680C0` (реакция, guard,
  deflect, i-frames); где проверяется команда для хитбокса. По крашу: взять module+offset и breadcrumb
  из `crash.rs`-строк в логах 1.0.11 (`%LOCALAPPDATA%\sekiro-coop\log.old.txt` обоих игроков).
- **B1, MVP (2–3 дня).**
  - Team 29 только у реплики и только на время дуэли (`CHR_TEAM`, `native.rs:88`). Команду локального
    игрока не трогать никогда.
  - Детур на вход `0xB6A040`: (жертва локальный, атакующий реплика) — отбросить полностью;
    (жертва реплика, атакующий локальный) — дать игре посчитать, снять HP-урон `+480`, posture `+484`,
    тип удара `+0x28`, id атаки, отправить надёжно с seq и временем.
  - Жертва применяет: основной вариант — синтетическая запись type 21 в очередь nsession (нативная
    реакция); запасной — posture через `0xBD4DE0(data, -d, 1)`, HP через сеттер `0xBD64E0` (без реакции
    и брейка: брейк — реакция удара, `posture.rs:14-17`).
  - Урон считается против защиты реплики с шаблоном CharaInitParam 1080100, не реальных статов друга
    (`native.rs:58`) — нужен множитель/пересчёт. Перекаты бьют хитбоксами AtkParam_Pc 210/211.
- **B2 (~2 дня).** Удар в i-frames жертвы отбрасывать, в guard урезать, deflect с ответом атакующему.
- **Несмертельные дуэли по умолчанию.** Удар, доводящий HP до ≤0, ставит HP = 1 и завершает дуэль
  (восстановить HP/posture обоим, вернуть команду реплики). Это убирает краш при смерти целиком.

### Краш при смерти [ARV]
Пути мода при смерти (`bossrules.rs:1736-1800`, `debuff.rs:74-76`, `persist.rs:477-530`,
`resurrect.rs`, livesync DEATH_GUARD, EV_DEATH) читают память и к убийце не обращаются → краш в коде игры.
Гипотезы: H1 team 29 у локального игрока запускает путь смерти фантома/вторженца (наследие DS3) с
пустым FrpgSessionManager; H2 убийца — PlayerIns класса 2, начисление/имя/награда через несуществующую
запись сессии; H3 для краша друга — смерть реплики при team 29 (HP 0 из type 1, `native.rs:1250-1256`).
Тот же класс ошибки Tihvert нашёл в issue #3 (поиск персонажа после катсцены).
Защита: несмертельные дуэли; локальная команда неизменна; если смерть разрешена — финальный удар без
атакующего (только сеттер HP); пометка `pvp_death`, чтобы смерть не шла в дебафф, wipe, spectate latch, EV_DEATH.

## C. Ныряние без «Техники дыхания Мибу»

- Веб: по Paramdex (SDT) ворота — не event-флаг, а владение предметом: `EquipParamGoods.actionUnlockParamId`
  → `ActionUnlockParam.action00` («бесконечное дыхание»), «разблокируется, если есть хотя бы один
  отмеченный предмет». Точный goods id техники не найден (Smithbox).
- Код: в репе про mibu/dive/breath ничего нет. Гипотезы агента-кодера: (1) общий event-флаг из мира хоста
  через join-снапшот / live sync / ownworld MIRROR; (2) keyitems doctor/reconcile поставил флаги без
  предмета (строки `doctor`, `You are missing`, `reconcile:`); (3) SpEffect; (4) hkbsync — маловероятно.
- Если ворота действительно предметные, флаговые гипотезы отпадают, остаётся: предмет всё же есть
  (проверить вкладку ключевых предметов внимательно, у хоста тоже), либо что-то в сборке трогает
  EquipParamGoods в памени (`custom_icons`, кооп-предметы 999997–999999 скопированы с шаблона 3020).
- Тест: нырять (а) на обычном сейве S0000.sl2, (б) на кооп-сейве без подключения, (в) подключившись.
  F11 у рва (`state_log = 1`) даёт список SpEffect и флаги за 2 с. Разбор `c0000.hks`
  (WitchyBND → `chr\c0000.behbnd.dcx`) покажет точное условие перехода в ныряние.
